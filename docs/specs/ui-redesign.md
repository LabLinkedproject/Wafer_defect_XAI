# 화면 전면 개편 명세

2026-11-16 사용자와 정한 내용. 구현 전 기준 문서다.

## 목적
스캔 콘솔(`/scan`)과 분석 대시보드(`/analysis`)를 **한 화면 흐름**으로 다시 만들고, 지금 환경(근접 촬영, 원점 = 웨이퍼 중심)에서 쓰지 않는 기능을 뺀다.

## 대상과 환경
- **주 사용자:** 전시·발표 시연이 우선이다. 팀 검증 도구(정답 기록)는 접어 둔다.
- **표시 기기:** 노트북 화면과 큰 모니터·프로젝터 둘 다. 화면 폭에 따라 배치가 바뀌어야 한다. 큰 화면에서는 글자와 숫자를 키운다.
- **분위기:** 밝은 산업용 계측기. 흰 바탕에 절제된 색을 쓰고, 웨이퍼 사진과 수치가 주인공이다.

## 한 화면 흐름 (위에서 아래로)
0. **상단 상태 줄:** 장비 연결, 원점 지정 여부, 카메라, 현재 스캔 이름
1. **스캔**
   - 시작·정지 버튼
   - 스캔 중에는 웨이퍼 맵 자리에 찍힌 다이 사진이 하나씩 채워진다. 옆에 작은 실시간 카메라를 둔다.
   - 합성과 검출 단계, 남은 시간을 표시한다.
   - 끝나면 결과로 자동 전환한다. 새로고침이 필요 없어야 한다.
2. **결과**
   - 웨이퍼 맵은 "실측 맵 / 결과(템플릿 + 검출)"를 바꿔 볼 수 있다.
   - 다이 판정 맵과 다이 상세를 함께 둔다.
3. **판정:** 최종 패턴과 패턴 점수(판정선 표시). 결함 유형 비율은 작게 둔다.
4. **근거 (XAI):** 판정에 기여한 다이와 반사실 설명
5. **원인과 조치:** 원인 가설, 다음 확인 항목, 권장 조치, 레시피 파라미터
6. **엔지니어 판정 기록:** 판정 확인·수정을 재학습 데이터로 남긴다.

**접힌 패널 (기본 닫힘)**
- **장비:**
  - 조그 패드
  - "여기를 원점으로", 갠트리 원점으로 이동
  - 맵 다시 합성
  - 이전 스캔 불러오기
- **실물 검증 기록:** 정답 입력. 혼동행렬은 화면에 표시하지 않고 데이터로만 남긴다.

## 빼는 것
- 시뮬레이션(시나리오) 입력. 관련 API: `/api/adc/scenario`, `/api/adc/input.jpg`, 시나리오 코드
- 촬영 환경 점검 (`/api/scan/light`)
- 설정 폼 (`/api/scan/config` 화면 입력). 설정은 `scan_config.json` 파일로만 바꾼다.
- 스캔 범위 확인과 측정값 정렬 (`/api/scan/bounds`, `/api/scan/align`)
- 웨이퍼 중심 버튼 2개 (`/api/gantry/wafer-center`, `/api/scan/set-center`)
- 두 페이지 구조. `/scan`과 `/analysis`는 새 화면 `/`로 넘긴다.

## 기본값으로 정한 것 (사용자가 바꿀 수 있음)
- **남기는 세부 카드:** 존별 점유율, 둘레 방향 분포, Stain 영역, 위험도 구성, 수율. 각 단계 안의 "자세히"로 접어서 남긴다.
- **빼는 카드:** "현재 모델 구성과 교체 계획" 표

## 바꾸지 않는 것
- 검출, 합성, 패턴 판정 모델, 정답 기록의 백엔드 로직. 화면이 쓰는 API 응답 형식은 필요한 만큼만 고친다.
- 기술: Flask 템플릿과 순수 HTML·CSS·JS. 빌드 단계가 없고, 새 프레임워크를 들이지 않는다 (Ponytail 원칙).

## 도구
- **Impeccable:** 기존 제품을 다시 디자인하는 일이라 이것을 쓴다. 먼저 `/impeccable init`으로 디자인 기준을 잡고, 구현 뒤 `/impeccable audit`과 `polish`를 한다.
- **Hallmark:** 쓰지 않는다. 새 사이트가 아니라 기존 화면을 다시 만드는 일이기 때문이다.
- **Ponytail, `/ponytail-review`, `/code-review`:** 마무리 검토에 쓴다.

## 완료 기준
- 페이지를 열고 "스캔 시작" 한 번으로 촬영 → 결과 → 판정·근거·조치까지 새로고침 없이 이어진다.
- 노트북 폭(약 1366 px)과 큰 화면(1920 px 이상)에서 가로 스크롤이 생기지 않는다. 키보드로 주요 버튼을 쓸 수 있고, 글자 대비가 충분하다.
- 빼기로 한 기능의 화면 요소, JS, API가 남아 있지 않다.
- 기존 테스트(`tests.test_adc`, `test_detect`, `test_stitch`)가 통과하고, 브라우저 콘솔 오류가 없다.
